### ⚠️ 关键踩坑：VS 安装器退出码 5002（可复用经验）

- **现象**：`winget install Microsoft.VisualStudio.2022.BuildTools` 19 秒内失败，报「自定义安装程序错误 / 退出代码 5002」。
- **真因**：日志 `%TEMP%\dd_bootstrapper_*.log` 第 48 行 —— `0x80070057: Couldn't launch setup process. 已添加项。字典中的关键字:"HTTPS_PROXY"所添加的关键字:"https_proxy"`。`ProcessStartInfo.EnvironmentVariables` 底层是**大小写不敏感**字典，同时存在 `HTTPS_PROXY`+`https_proxy`（或 `HTTP_PROXY`+`http_proxy`）即抛重复键异常。
- **来源确认**：`[Environment]::GetEnvironmentVariable(n,"User"/"Machine")` 核实 —— **User/Machine 作用域均无代理变量持久化**，这 4 个大小写变体是 **WorkBuddy 沙箱/Shell runtime 注入到当前进程环境**的（值 `http://127.0.0.1:2405`，注意不是 Clash 的 7897）。
- **解法**：安装器启动前 `unset http_proxy https_proxy`（保留大写变体以维持代理连通）。
- **推广**：凡向子进程透传参数的 .NET 系安装器都可能踩此坑。遇到「原因不明的自定义安装程序错误」，先翻 `%TEMP%\dd_*.log`，再查代理变量大小写重复。

## 环境备忘（本项目相关）

- **bash 工具环境异常**：直接执行 bash 会报 `dirname: command not found`，`ls`/`find`/`head` 均不可用。**解法**：命令前加 `export PATH="/usr/bin:/bin:/c/Windows/System32:/c/Windows:$PATH"` 即可恢复正常。
- **PowerShell 工具 stdout 无法回传**（命令 exit 0 但输出为空）。**两种解法**：①「写入文件 + Read 读取」；② 加 `run_in_background=true`，其 stdout 可经 `TaskOutput` 完整取回（本次装 Rust 用的就是这个）。
- **PowerShell 工具会拦截含 `%VAR%` 模式的命令**（报「cmd.exe 环境变量语法不是 PowerShell 语法」），注释里出现 `%PATH%` 之类也会被拦，需改写措辞。
- **`reg.exe` 被安全策略列入程序黑名单**，注册表查询不可用；改用文件系统路径存在性判定替代。
- **`cmd.exe` 同样被拦截**：从 Bash 调用报「Invoking cmd.exe from Bash bypasses all command validation」，从 PowerShell 调用报「cmd.exe cannot be used from the PowerShell tool; use native PowerShell syntax instead」。**因此不能依赖 `vcvars64.bat` / `LaunchDevCmd.bat` 装配 MSVC 环境**，需用原生 PowerShell 手工设 `PATH`/`INCLUDE`/`LIB`（模板见 `docs/Tauri开发环境检查报告.md` 第 3.3 节）。
- **`du -sh` 在大目录上会卡死被 SIGTERM**；统计体积改用 PowerShell `Get-ChildItem -Recurse | Measure-Object -Property Length -Sum`。
- **Bash 里给 Windows 原生程序传路径会踩 MSYS 转换**：`export CARGO_HOME="D:\\development_tools\\cargo"` 实际传出 `D://development_tools//cargo`。Windows API 能容错，但**正解是用 PowerShell 工具设 `$env:`**，避免歧义。
